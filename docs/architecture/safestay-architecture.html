SafeStay London 시스템 구조

런던 LSOA 치안 주제도 위에 Airbnb 숙소와 사용자가 등록한 맛집을 보여주는 웹앱입니다. 화면은 Thymeleaf 한 페이지(map.html)에 메뉴별 패널을 끼워 넣는 구조이고, 백엔드는 Spring Boot, DB는 PostGIS입니다.

1. 요청이 흐르는 길

사용자 요청 시 공간 연산(PostGIS) 앱 시작 시 1회 서버·DB를 쓰지 않음

2. 앱이 켜질 때 일어나는 일

DB 프로필로 실행하면 서버가 요청을 받기 시작한 뒤 아래 세 Runner가 순서대로 돕니다. 이미 처리된 DB에서는 각 단계가 아무것도 하지 않고 넘어갑니다.

  1. SchemaPatchRunner

    ddl-auto: update가 바꾸지 못하는 기존 컬럼을 맞춥니다. safety_zones.geometry를 MultiPolygon으로, restaurants.user_id를 nullable로.

  2. SafetyZoneDataLoader

    safety_zones가 비어 있으면 london-lsoa-themes.json에서 LSOA 4,994개를 넣고 GIST 공간 인덱스를 만듭니다.

  3. AccommodationDataLoader

    accommodations가 비어 있으면 london-airbnb-listings.json을 넣으면서 좌표로 구역을 찾아 safety_zone_id를 채우고, 자치구·방 유형으로 숙소 이름을 만듭니다.

5. 구조상 알아둘 점

  • 나만의 장소 지도는 저장되지 않습니다. user_custom_layers, custom_markers 테이블은 있지만 API가 없어서 그린 내용은 새로고침하면 사라집니다.
  • 로그인이 없습니다. users 테이블은 비어 있고, 맛집은 등록자 없이(user_id null) 저장됩니다.
  • 스키마 변경은 자동으로 반영되지 않습니다. ddl-auto: update는 컬럼 추가만 합니다. 기존 컬럼의 타입이나 NOT NULL을 바꾸면 SchemaPatchRunner에 보정을 추가해야 합니다. 2026-10-24 배포 장애의 원인이었습니다.
  • DB 없이도 화면은 뜹니다. run.sh는 map-only 프로필로 실행되어 DB 관련 Bean이 빠집니다. 이때 숙소 찾기와 맛집 등록은 동작하지 않습니다.
  • 첫 기동 직후 잠깐은 등록이 실패할 수 있습니다. 서버가 요청을 받기 시작한 뒤 적재가 진행되므로, 그 사이에 맛집을 등록하면 "구역 밖" 오류가 납니다.
