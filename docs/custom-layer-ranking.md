# 개인 관심 여행지 순위

## 사용 방법

1. 나만의 장소 지도에서 마커·선·다각형·사각형·원을 등록한다.
2. 조건 조회 탭에서 원하는 월·시간을 적용한다. 조회 전이거나 조건 초기화 후라면 전체 월·시간을 사용한다.
3. **여행지 찾기** 탭에서 추천 순서를 선택하고 **여행지 순위 계산**을 누른다. 적용한 조회 조건은 이 탭에서도 사용한다.
4. 지역별 관심 항목 수와 연간 사건률을 확인한다. 결과를 누르면 해당 지역 범위로 지도가 이동한다.
5. 지역 아래 **포함된 장소·도형 보기**를 펼치면 집계된 항목의 이름·도형 종류·월·시간을 확인할 수 있다. 항목을 누르면 해당 도형으로 지도가 이동한다. 더미 예시 목록에서도 같은 동작을 사용할 수 있다.

숨긴 항목은 제외한다. 등록 전 도형은 먼저 등록하거나 삭제해야 계산할 수 있다.
서버 저장 전 편집 내용도 집계하며 계산 자체는 개인 레이어 저장본이나 DB를 변경하지 않는다.
항목·좌표·조회 조건·정렬 기준이 바뀌면 이전 결과를 지우고 재계산을 안내한다.

### 더미 데이터 예시

여행지 찾기 탭에서 **더미 데이터로 순위 예시 보기**를 누르면
`static/data/personal-ranking-example.json`의 런던 장소·동선·구역 8개만 별도로 계산한다.
실제 항목을 추가·수정하거나 저장하지 않으며, 현재 월·시간 조회 조건도 예시에 적용하지 않는다.
마커·선·다각형·원·사각형을 포함하고 ‘사용한 예시 데이터 보기’에서 항목을 확인할 수 있다.
순위 결과와 함께 같은 도형 8개를 지도에 미리보기로 표시한다. 조건이나 정렬을 변경하거나 다른 탭·메뉴로 이동하면 미리보기가 사라진다.
순위 숫자를 고정해 보여주는 것이 아니라 실제 행정구역 교차 API로 계산한다.
Google 지도를 로드하지 못하는 경우에도 예시 순위 목록은 계산할 수 있다.
기존 항목으로 돌아가려면 ‘여행지 순위 계산’을 누른다.

## 기존 행정구역 재사용

새 행정구역을 만들지 않는다. 기존 `map.html`과 `SafetyZoneDataLoader`가 사용하는
`static/data/london-lsoa-themes.json`의 Polygon/MultiPolygon 경계로 교차를 판정한다.
기존 지도 순위의 `properties.borough` 값으로 묶는다.

- 같은 항목이 같은 행정구 내 여러 LSOA 또는 MultiPolygon 조각에 걸쳐도 **한 번**만 센다.
- 서로 다른 행정구에 걸친 항목은 각 행정구에 한 번씩 포함한다.
- 경계선·꼭짓점에 닿는 경우도 포함한다.
- 구역 내부의 빈 공간(hole)은 제외한다. 도형이 그 경계에 닿으면 포함한다.
- 좌표가 같아도 서로 다른 항목 ID라면 각각 센다.
- 관심 항목이 없는 지역은 표시하지 않는다. 지역별 수의 합은 전체 항목 수보다 클 수 있다.

## 교차 판정과 치안 지표

마커·선·면은 JTS `intersects`를 사용한다. STRtree로 외접 범위가 겹치는 후보만 검사한다.
원은 중심점의 포함 여부와 경계선까지의 구면 거리를 반지름(m)과 비교한다.
중심점만으로 판정하거나 다각형의 일부 표본점만 검사하지 않는다.
지구 반지름은 기존 `draw.js`와 같은 6,371,008.8m이며 원 경계 비교 오차 허용치는 1cm다.
구면 모델과 웹 표시용 단순화 경계에 따른 근사이므로 측량 수준의 판정은 아니다.

치안 지표는 기존 지도 순위와 동일하게 계산한다.

```text
행정구 연간 사건률 = 유효한 LSOA 사건 수 합 / 해당 LSOA 인구 합 × 1,000
```

LSOA별 사건률의 단순 평균을 사용하지 않는다. 데이터가 없거나 분모가 0이면 결측으로 처리하고
사건률 비교에서 마지막에 둔다. 기존 데이터의 2024년 연간 사건·인구 기준이며 안전을 보장하지 않는다.
치안 등급은 기존 GeoJSON 구간 기준을 사용한다.

| 기준 | 우선순위 |
|---|---|
| 관심 장소 많은 순 | 교차 항목 수 내림차순 → 사건률 오름차순 → 지역 이름 |
| 사건률 낮은 순 | 사건률 오름차순 → 교차 항목 수 내림차순 → 지역 이름 |

임의 가중 점수는 사용하지 않는다. 번호는 정렬 후 표시 순번이며 동률에도 지역 이름 순으로 부여한다.

## API와 저장소

`POST /api/custom-layers/ranking?order=interest` 또는 `order=safety`

요청은 저장 API와 같은 `{ "features": [...] }` 객체다. 화면에서 적용한 월·시간에 맞고
표시 중인 등록 항목만 보내며 사진은 `null`로 제외한다. 서버는 입력을 검증하고 숨김 항목도 제외한다.
최대 1,000항목이며 잘못된 좌표·중복 ID·길이 또는 면적이 없는 도형·자기 교차 다각형은 거부한다.

응답:

- `analyzedCount`: 분석한 표시 항목 수
- `matchedCount`: 최소 한 행정구와 교차한 항목 수
- `outsideCount`: 어느 행정구와도 교차하지 않은 항목 수
- `regions`: `rank`, `borough`, `count`, `incidentRate`, `safetyLevel`, `bounds`, `featureIds`

항목 저장·사용자 조회·DB 스키마 변경 없이 계산하는 읽기 전용 기능이며 `map-only`에서도 동작한다.
지도와 일치하도록 GeoJSON을 기준으로 하므로 DB에서 별도 변경한 치안 값은 반영하지 않는다.
경계·지표는 서버 시작 시 읽어 재사용한다. 원본 파일 교체 후 서버 재시작이 필요하다.

## 검증과 로컬 확인

테스트는 공유 경계, 동일 행정구 내 중복, 여러 행정구, hole, MultiPolygon, 원의 반지름과 접점,
구역 밖·숨김 항목, 정렬과 치안 결측을 확인한다. 실제 GeoJSON을 사용한 HTTP 테스트는
DB 없이 집계하고 저장본을 바꾸지 않는지 확인한다. JavaScript 테스트는 조회 필터·최신 좌표·사진 제외,
오래된 응답 무시·실패 후 재시도 및 Google 지도 좌표를 읽을 수 없는 경우를 확인한다.

Google Maps가 `RefererNotAllowedMapError`를 표시하면 현재 실행 주소가 키의 허용 웹사이트 목록에
있는지 확인해야 한다. 키 값이나 개인 접속 설정을 공유 파일에 넣지 않는다.
